# ADR 005 — شركة واحدة: لا Multi-Tenancy

**الحالة:** مقبول · **التاريخ:** 2026-08

## السياق
طُرح سؤال بناء المنصة كـ SaaS متعدد العملاء، وحُسم: **تطبيق داخلي لشركة بلدية واحدة**.

## القرار
- لا جدول `organizations` ولا `organization_id` — الجداول في الجذر مباشرة.
- لا فوترة ولا Onboarding ولا بوابة مشغّل منصة.

## مسار التراجع (إن تغير القرار يوماً)
1. migration جديد يضيف `organizations` + `organization_id` في كل جدول (قيمة ثابتة).
2. تحديث RLS policies بشرط العزل.
3. طبقة TenantContext في الواجهة.
التكلفة معقولة **لأن** كل الوصول للبيانات يمر عبر SDK واحد (ADR 002) — هذا هو التأمين الحقيقي.
