# تشغيل إشعارات Web Push

## المتطلبات

يستخدم النظام مفاتيح VAPID القياسية. المفتاح العام فقط يوضع في بناء الواجهة باسم `VITE_VAPID_PUBLIC_KEY`. المفتاح الخاص لا يوضع في المستودع أو المتصفح، بل يضاف إلى Supabase Edge Function Secrets باسم `VAPID_PRIVATE_KEY`، مع `VAPID_PUBLIC_KEY` و`VAPID_SUBJECT`.

يمكن توليد الزوج محلياً بأداة `web-push generate-vapid-keys` ثم حفظه مباشرة في مدير الأسرار. لا تُرسل المفاتيح في المحادثات أو البريد.

## النشر

1. طبّق migration رقم `00096`.
2. انشر `notification-push-dispatch` مع تحقق JWT.
3. اضبط أسرار VAPID في Supabase.
4. ابنِ الواجهة بعد ضبط المفتاح العام.
5. جدْول استدعاء Edge Function كل دقيقة باستخدام service-role من مدير أسرار آمن، ليعمل Push حتى عندما تكون التطبيقات مغلقة.
   ✅ **منفَّذ في الهجرة `00407_push_dispatch_schedule.sql`** (مهمة `notification-push-dispatch-minute`).
   قبل 00407 لم تكن الجدولة موجودة ⇒ لم يُرسل أي إشعار وهاتف المستخدم مغلق (٠ اشتراك · ٠ إرسال).
6. **يجب أن يطابق** `VITE_VAPID_PUBLIC_KEY` في بناء الواجهة قيمة `VAPID_PUBLIC_KEY` في أسرار الخادم.
   اختلافهما يعني: يسجّل الجهاز اشتراكًا ثم يفشل كل إرسال إليه (401/403 من خدمة Push).
   لتغييرهما: ولّد زوجًا واحدًا واستخدم **نفس** المفتاح العام في البناء وفي الخادم، والخاص في الخادم فقط.

لا يوضع service-role داخل SQL مكشوف أو داخل الواجهة. استدعاء المستخدم للدالة يوزع طابوره هو فقط؛ الاستدعاء المجدول الموثوق يوزع جميع الطوابير.

## توافق الأجهزة

- Android والحاسوب: متصفح حديث، HTTPS، ومنح إذن الإشعارات.
- iPhone/iPad: iOS 16.4 أو أحدث، وإضافة التطبيق إلى الشاشة الرئيسية قبل طلب الإذن.
- صوت إشعار الخلفية تحدده إعدادات نظام التشغيل. الصوت أثناء فتح التطبيق ينفذه التطبيق وفق تفضيل المستخدم.
