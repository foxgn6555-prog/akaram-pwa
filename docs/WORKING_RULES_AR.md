# شروط العمل الإلزامية — جزيرة الأكارم PWA

> هذه الشروط **ملزمة** لكل جولة عمل على هذا المستودع، ولا يجوز مخالفتها أو تجاوزها
> جزئياً. أي طلب لاحق يخالفها يُوقف ويُطلب تأكيد صريح من صاحب المشروع أولاً.

## 0) القاعدة الحاكمة

**لا مهاجرة تُطبَّق، ولا فرع يُدمج، ولا نسخة تُنشر قبل اجتياز كل البوابات أدناه.**
التحقق هو شرط الدمج، لا خطوة تالية له.

## 1) التسلسل الإلزامي قبل الدمج (بالترتيب، بلا اختصار)

| # | البوابة | الأمر / الوسيلة | شرط النجاح |
|---|---|---|---|
| ١ | فحص **كل** المهاجرات | `node scripts/db-migrations-test.mjs` (قاعدة فارغة) + مواءمة `supabase_migrations.schema_migrations` الإنتاجي مع `supabase/migrations/*.sql` | كل الملفات تُطبَّق، وصفر معرّفات ستُعاد تنفيذها |
| ٢ | حارس الانحراف | `npm run check:migrations` | خروج `0` |
| ٣ | اختبارات المنصة | `npm test` ثم `npm run test:coverage` | كلها خضراء والعتبات 70/70/70/70 محققة |
| ٤ | اختبارات SQL | تشغيل الحاجز المحصّن (`scripts/db-tests.sh`) محلياً أو عبر CI | صفر إخفاق في الحاجز |
| ٥ | البناء | `npm run env:check && npm run lint && npm run typecheck && npm run build` | نجاح كامل، `dist/` صالح |
| ٦ | الأسرار | `bash scripts/check-secrets.sh` | لا أسرار في الملفات المتتبعة |
| ٧ | تقرير المخاطر | مكتوب في الرد/PR: ما تغيّر، الأثر على القاعدة الحيّة، خطة التراجع | مقبول من صاحب المشروع |
| ٨ | الدمج | إلى `port-00134` فقط | بعد موافقة صريحة على التقرير |

لا يُسمح بتخطّي بوابة لأن «التغيير صغير»، ولا بتعديل عتبة أو تعطيل اختبار لتمرير الفحص.

## 2) قواعد المهاجرات (migrations)

- **لا تُعدَّل مهاجرة سبق تطبيقها**؛ الإصلاح يكون بملف مهاجرة جديد.
- **لا `supabase db push` إلى الإنتاج** قبل أن يكون حارس الانحراف أخضر، لأن بعض الملفات
  ليست آمنة التكرار (مثال: `20261117160000_permission_catalog_disbursements` يحذف
  `permission_write_bindings` بالكامل).
- أي معرّف طُبّق على الإنتاج بمعرّف مختلف يُسجَّل في `supabase_migrations.schema_migrations`
  بـ `INSERT` فقط (بلا إعادة تنفيذ)، ثم تُحدَّث لقطة `docs/migration-history.json`.
- أي تعديل على قاعدة الإنتاج نفسها يتطلب إذناً صريحاً لكل خطوة على حدة.

## 3) الدمج والنشر

- العمل يجري على فرع الجلسة `arena/<id>-akaram-pwa` فقط، وبعد اكتمال التحديثات يُدمج
  في `port-00134`.
- الدفع إلى `port-00134` يُشغّل `.github/workflows/deploy.yml` الذي يبني `dist/` ويرفعه
  إلى **فرع `deploy`** (فرع أصول واحد، orphan)، ومنه يجري الرفع إلى استضافة هوستنجر
  على النطاق `jazirat-alakharim.com`. لذلك:
  - **`port-00134` = المصدر**، و **`deploy` = ناتج بناء** — لا يُحرَّر `deploy` يدوياً.
  - الدمج مع `port-00134` = نشر مباشر. لا دمج قبل اكتمال §1.
- بعد كل نشر يُتحقق من:
  - `https://jazirat-alakharim.com/version.json` يحمل `4.0.0+<sha>` للالتزام المدموج،
  - `index.html` يعمل (عنوان الصفحة الصحيح)،
  - `sw.js` و`index.html` بلا كاش قديم (`no-cache` من `.htaccess`)،
  - مطابقة محتوى فرع `deploy` لآخر بناء في Actions.

## 4) الأمان

- لا أسرار ولا مفاتيح في المستودع ولا في متغيرات `VITE_*` (المفتاح السري `sb_secret_*` ممنوع
  في الواجهة — `scripts/check-env.ts` يمنع البناء).
- لا تُطبع قيم الأسرار في السجلات أو التقارير.
- لا تُنشأ مفاتيح ولا تُحذف ولا تُغيَّر إعدادات Auth الحيّة دون طلب صريح.

## 5) التوثيق

كل جولة تنتج سجلاً مكتوباً: ما فُحص، بماذا، النتائج بأرقامها، وما لم يُتحقق منه وسببه.
الإخفاق لا يُخفى ولا يُستثنى من التقرير.
