# تحليل تكامل LVN GPS مع منصة الأكرم

تاريخ التحليل: 2026-09-10  
المصدر: `LVN_API_Devices_Reports.json`  
حالة التحليل: تحليل ساكن للتوثيق فقط؛ لم تُنفذ طلبات حية ولم تُستخدم بيانات دخول.

## 1. الخلاصة التنفيذية

الـAPI مناسب لبناء صفحة GPS داخل غرفة العمليات. يوفر أربع قدرات أساسية:

1. تسجيل الدخول والحصول على `user_api_hash`.
2. جلب جميع الأجهزة وآخر حالة مع دعم الصفحات والفلاتر.
3. جلب التغييرات الحية بصورة جزئية باستخدام مؤشر `time`.
4. جلب سجل جهاز وإنشاء/تنزيل تقارير LVN.

التصميم الصحيح هو موصل خادمي آمن يحفظ نسخة تشغيلية في Supabase. لا يجوز اتصال واجهة المتصفح بـLVN مباشرة، ولا تخزين البريد أو كلمة المرور أو `user_api_hash` في React أو قاعدة البيانات العامة.

## 2. نقاط الاتصال المؤكدة

| الوظيفة | الطريقة | المسار | الاستخدام المقترح |
|---|---|---|---|
| تسجيل الدخول | POST | `/login` | خادمي فقط، multipart/form-data |
| قائمة الأجهزة | GET | `/get_devices` | مزامنة كاملة وصفحات وربط أولي |
| تفاصيل جهاز | GET | `/get_devices` مع `id` | تفاصيل جهاز واحد |
| التحديثات الجزئية | GET | `/get_devices_latest` | المزامنة الحية باستخدام `time` |
| سجل جهاز | GET | `/get_history` | تحميل عند الطلب لفترة محددة |
| التقارير المحفوظة | GET | `/get_reports` | استعراض إعدادات تقارير LVN |
| أنواع التقارير | GET | `/get_reports_types` | جلب الأنواع الحالية وعدم تثبيتها في الكود |
| بيانات إنشاء التقرير | GET | `/add_report_data` | الأجهزة، السياجات، الصيغ، الأنواع والفلاتر |
| إنشاء تقرير فوري | POST | `/generate_report` | يعيد رابط ملف عند `status=3` |
| حفظ تقرير مجدول | POST | `/add_report` | يؤجل للمرحلة الثانية |
| سجل التقارير | GET | `/reports/logs` | سجل التقارير المولدة/المرسلة |
| تنزيل تقرير | GET | `/reports/logs/{id}/download` | تنزيل الملف عبر الخادم |

العنوان الأساسي المؤكد:

```text
https://track.gpslvn.iq/api
```

## 3. المصادقة

- `/login` يستقبل `email` و`password` بصيغة multipart/form-data.
- الاستجابة الناجحة تعيد `user_api_hash`.
- جميع الطلبات اللاحقة ترسله query parameter مع `lang`.
- عند HTTP 401 يجب حذف hash من الذاكرة وتسجيل الدخول مرة واحدة ثم إعادة الطلب مرة واحدة فقط.
- الخيار `as` في تسجيل الدخول يسمح بالدخول كمستخدم آخر؛ لن تدعمه المنصة لأسباب أمنية.

### ملاحظة أمنية عاجلة

يحتوي ملف التوثيق على قيمة افتراضية تشبه API hash داخل أمثلة بعض معاملات التقارير. قد تكون قيمة توضيحية، لكن بما أن الملف موجود في مستودع GitHub فيجب اعتبارها مكشوفة إن كانت حقيقية وطلب تدويرها من المزود. لن نستخدمها أو ننسخها إلى الكود.

## 4. بنية بيانات الأجهزة

الاستجابة الكاملة لـ`get_devices` منظمة كمجموعات، وكل مجموعة تحتوي `items`. الحقول المهمة في كل جهاز:

- `id`: المعرف الصحيح الذي يجب حفظه واستخدامه في التقارير.
- `name`, `online`, `alarm`.
- `time`, `timestamp`, `acktimestamp`.
- `speed`, `lat`, `lng`, `course`, `altitude`.
- `power`, `address`, `protocol`, `driver`.
- `sensors`, `services`, `tail`.
- `distance_unit_hour`.
- `device_data`: IMEI، SIM، VIN، اللوحة، رقم التسجيل، المالك، الموديل، المجموعة، حدود الحركة والوقود وغيرها.

يجب عدم استخدام IMEI أو `traccar_device_id` بديلاً عن `id` في طلبات التقارير.

## 5. المزامنة الحية

استجابة `get_devices_latest` تحتوي:

- `items`: الأجهزة التي تغيرت فقط.
- `events`: أحداث جديدة إن وجدت.
- `time`: المؤشر المطلوب للطلب التالي.
- `version`: إصدار خدمة LVN.

الخوارزمية:

1. مزامنة كاملة لكل صفحات `get_devices`.
2. حفظ `time` من آخر استجابة حية ناجحة.
3. طلب `get_devices_latest?time=<cursor>`.
4. دمج العناصر حسب LVN device id.
5. حفظ كل موقع أحدث من الموقع المخزن فقط.
6. تحديث cursor بعد نجاح المعاملة كاملة، وليس قبلها.
7. الجهاز الغائب عن الاستجابة الجزئية لا يعد محذوفاً أو غير متصل.
8. عند فقد cursor أو رفضه تنفذ مزامنة كاملة مصالِحة.

التردد المقترح عند البداية: 60 ثانية، ثم يخفض إلى 30 ثانية فقط إذا أكدت الشركة حدود الطلبات.

## 6. سجل الحركة

`get_history` يحتاج:

- `device_id`.
- `from_date`, `from_time`.
- `to_date`, `to_time`.
- `lang` و`user_api_hash`.
- `snap_to_road` اختياري.

ويعيد نقاط/مقاطع الحركة إضافة إلى مؤشرات مثل:

- المسافة الكلية.
- أعلى سرعة.
- مدة الحركة.
- مدة التوقف.
- ساعات المحرك والخمول والعمل.
- استهلاك الوقود إن كان الحساس متوفراً.

سجل التاريخ سيجلب عند الطلب ولا يدخل في مزامنة الدقيقة الدورية لتقليل الحمل.

## 7. التقارير

الصيغ الموثقة مثالياً: HTML، XLS، PDF، PDF أفقي. يجب جلب الصيغ الفعلية من `add_report_data` بدلاً من تثبيتها.

أنواع التقارير الموثقة تشمل:

- معلومات عامة.
- معلومات عامة مدمجة.
- الحركة والتوقفات.
- الحركة والتوقفات/السياجات.
- ورقة الرحلة.
- تجاوز السرعة والسرعة المنخفضة.
- دخول/خروج السياج.
- الأحداث.
- مستوى الوقود والتعبئة والسرقة.
- الحرارة.
- RAG.

جسم إنشاء التقرير يدعم العنوان والنوع والصيغة والأجهزة والفترة والوقت وحد السرعة والسياجات وحد التوقف وإظهار العناوين.

عند نجاح `generate_report` وإرجاع `status=3` يجب تنزيل الملف من `url`. إذا كان الرابط نسبياً يحل مقابل مضيف LVN. لأسباب أمنية لا يسمح الموصل بتنزيل رابط من مضيف آخر، لمنع SSRF.

التقارير المجدولة و`send_to_email` تؤجل حتى التأكد من سلوك الجدولة والبريد وصلاحية رابط التنزيل.

## 8. نموذج التخزين المقترح

- `gps_providers`: حالة المزود، cursor، آخر نجاح وخطأ.
- `gps_devices`: بيانات الجهاز الثابتة والمعلومات التعريفية.
- `gps_vehicle_bindings`: ربط الجهاز بآلية الكراج مع مصدر وثقة المطابقة.
- `gps_latest_positions`: آخر موقع فقط لكل جهاز.
- `gps_position_history`: المواقع التاريخية الجديدة دون تكرار.
- `gps_events`: أحداث LVN والأحداث المحسوبة.
- `gps_sync_runs`: سجل كل مزامنة وعدد العناصر والمدة والخطأ الآمن.
- `gps_report_jobs`: طلبات التقارير وحالتها ومرجع الملف دون حفظ hash.

كل الجداول تطبق RLS. القراءة لغرفة العمليات والمخولين، والكتابة للموصل الخادمي فقط.

## 9. التطبيع والتحقق

- تحويل الأرقام النصية إلى أرقام مع الاحتفاظ بـnull عند القيم `-` أو الفارغة.
- التحقق العالمي من latitude وlongitude، مع وسم الموقع خارج العراق للمراجعة دون حذفه.
- عدم السماح لموقع قديم باستبدال موقع أحدث.
- مفتاح منع التكرار: المزود + device id + device timestamp.
- التعامل مع `sensors`, `services`, `tail` سواء وصلت كمصفوفة أم JSON داخل string؛ التوثيق يعرض الشكلين.
- استخدام وقت GPS كوقت حدث ووقت الخادم كوقت استلام.
- تأكيد timezone حساب LVN؛ أمثلة التوثيق تظهر احتمال فرق بين الوقت المعروض ووقت الخادم.
- إظهار وحدات السرعة حسب `distance_unit_hour` وعدم افتراض km/h قبل التحقق.

## 10. واجهة غرفة العمليات

المسار المقترح: `/ops-room/gps`.

### الصفحة الرئيسية

- إجمالي الأجهزة، المتصل، غير المتصل، المتحرك، المتوقف، غير المربوط، والتنبيهات.
- آخر مزامنة ومدتها وحالتها.
- خريطة ملونة وتجمع علامات عند كثرة الآليات.
- جدول أجهزة منظم مع البحث والفلاتر.
- زر مزامنة يدوية للمخول فقط.

### التفاصيل

- الموقع والسرعة والاتجاه والمحرك والطاقة والسائق والعنوان.
- بيانات الجهاز والآلية المرتبطة.
- المسار خلال فترة.
- مؤشرات المسافة والحركة والتوقف وأعلى سرعة.
- الأحداث والحساسات والخدمات.

### الربط

المطابقة المقترحة بالترتيب: VIN فريد، ثم لوحة موحدة وفريدة، ثم ربط يدوي. لا يعتمد اسم الجهاز وحده. تظهر قائمة منفصلة للأجهزة غير المربوطة والتعارضات.

## 11. التشغيل المحلي والنشر

في التطوير المحلي:

- الواجهة المحلية تقرأ Supabase فقط.
- Edge Function أو موصل محلي آمن يتصل بـLVN.
- الأسرار توضع في environment غير متعقب بـGit.
- يبدأ التشغيل بزر اختبار الاتصال ثم مزامنة كاملة يدوية.

في الإنتاج:

- تشغيل المزامنة المجدولة خادمياً.
- استخدام timeout وretry محدود وbackoff.
- حجب البريد وكلمة المرور والhash وكل query string الحساسة من السجلات.
- تنبيه غرفة العمليات عند تكرر الفشل.

## 12. الأمور غير المحسومة مع المزود

يلزم تأكيد ما يلي قبل الإنتاج:

1. حدود الطلبات rate limits.
2. أكبر فترة مسموحة للتاريخ والتقرير.
3. timezone حساب الشركة.
4. مدة صلاحية `user_api_hash` ورابط التقرير.
5. تعريف online/offline بالدقائق.
6. معنى حالات `status` و`alarm` والأحداث الفعلية.
7. وحدات السرعة والمسافة والوقود.
8. أقصى limit وعدد الأجهزة المتوقع.
9. هل `time` cursor شامل وآمن بعد الانقطاع الطويل.
10. شروط استخدام الخريطة والعناوين وsnap-to-road.
