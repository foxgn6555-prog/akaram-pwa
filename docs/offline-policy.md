# سياسة العمل دون اتصال (ADR 006 — الملخص التنفيذي)

## ما يعمل دون اتصال
| الجاهزية | الميزة | السلوك |
|----------|--------|--------|
| ✅ كامل | تصفح الصفحات المزارة | App Shell كاش |
| ✅ كامل | قراءة إشعار/تجاهله | client-wins + طابور |
| ✅ كامل | تسجيل حضور اليوم | client-wins + طابور |
| ✅ كامل | إنشاء طلب جديد | يُدرج محلياً "معلّق" ويُرسل عند العودة |
| ❌ محظور | أي كتابة مالية (رواتب/ميزانية) | server-wins — الزر يعطّل دون اتصال |
| ❌ محظور | رفع ملفات | يتطلب اتصالاً (Storage لا يُصفّر طابوراً) |

## القواعد الثلاث
1. كل تعارض يُحسم بمصفوفة `OFFLINE_POLICIES` — لا قرارات ارتجالية في المكونات.
2. `version` في الخادم حكم — طفرة بطبعة قديمة تُرفض دائماً.
3. المستخدم يرى دائماً: شريط Offline + عدّاد الطابور (OfflineBanner).

## مسار الترقية
localStorage → IndexedDB (`idb-keyval`) عند تجاوز 5MB أو 100 طفرة معلقة.

## سياسة التخزين المسبق (تحديث 00349 ج)
| الفئة | precache | بعد أول استخدام | السبب |
|------|----------|------------------|-------|
| App Shell + كل صفحات التطبيق + الخطوط | ✅ | — | التصفح الكامل بلا اتصال |
| صور الواجهة | — (NetworkFirst) | مهلة 5 ثوانٍ ثم الكاش | لا تُثقل التثبيت |
| **حزم التصدير**: `exceljs` · `jspdf` · `html2canvas` · `design-word` · `pdf` | ❌ مستبعدة | `CacheFirst` (حد 20 مدخلاً · 30 يوماً) | ≈2.3MB لا يدفعها من لا يصدّر |
| بيانات Supabase (`rest/auth/storage/functions`) | ❌ | ❌ NetworkOnly | لا كاش لبيانات حساسة |

**قبل:** 420 مدخلاً / 8.7MB لكل جهاز عند التثبيت. **بعد:** الحزم الثقيلة لا تُنزَّل إلا عند فتح شاشة تصدير فعلياً؛
ومن ثبّت ثم انقطع اتصاله قبل فتح شاشة تصدير سيرى رسالة خطأ واضحة في تلك الشاشة فقط، وبقية التطبيق يعمل.

## بصمة الإصدار
كل بناء يحمل `__APP_VERSION__` = `نسخة package.json + SHA` (تُحقن في `vite.config.ts`)، تُعرض في شريط
التحديث وفي `<html data-app-version>` وتُمرَّر إلى Sentry كـ `release` — فتكون كل الأخطاء منسوبة لبناء محدّد.
