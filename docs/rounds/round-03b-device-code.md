# الجولة ٣-ب — رمز موافقة الجهاز للحسابات الحساسة

**التاريخ:** 2026-11-20 · **الفرع:** `arena/0065458d-akaram-pwa`
**القرار:** الخيار ١ — رمز يُنشئه صاحب الحساب من جهازه الحالي.
**الحالة:** منفّذة ومختبرة محلياً — **لم تُدمج ولم تُنشر**.

---

## ١) المشكلة التي تُغلقها

قبل هذه الجولة: من يعرف **كلمة المرور فقط** لحساب حسّاس يفتحه من هاتفه ويضغط «الانتقال» ⇒ يطرد صاحب الحساب ويدخل مكانه.
بعدها: الانتقال إلى جهاز جديد لحساب من التسعة **لا يمرّ** إلا برمز موافقة صادر من جهاز صاحبه.

---

## ٢) كيف يعمل

| الحالة | السلوك |
|---|---|
| حساب عادي بلغ الحد | كما في الجولة ٣: انتقال بكلمة المرور بعد تأكيدها |
| **حساب حسّاس** بلغ الحد | لوحة الدخول تطلب **رمزاً من ٦ أرقام** + شرح كيف يُنشأ |
| صاحب الحساب | يفتح «أجهزتي» ← «إنشاء رمز الموافقة» ⇒ رمز صالح **١٠ دقائق**، يُستخدم **مرة واحدة** |
| رمز خاطئ | يُرفض ويُحتسب (٥ محاولات ثم يُبطَل الرمز) ويُسجَّل `switch_denied` |
| رمز صحيح | تُطبَّق الانتقالات: تُحذف الجلسات السابقة في الخادم ويُفتح الجهاز الجديد + `switch_approved` |
| **فقدان الجهاز** | تقنية المعلومات تُنهي جلسة الحساب من صفحته (بطاقة «جلسات الحساب») ويُسجَّل باسمها |

## ٣) ما نُفّذ

| # | العنصر | التفصيل |
|---|---|---|
| ١ | `device_switch_codes` | الرمز **مجزَّأ** (sha256) لا يُخزَّن صريحاً · `expires_at` ١٠ دقائق · `attempts` · `used_at`/`used_session` |
| ٢ | `app.user_has_sensitive_role` | التصنيف من جدول `sensitive_roles` — تعطيل الدور يُلغي الحساسية فوراً |
| ٣ | `device_switch_code_create` | لصاحب الحساب: يُلغي الرموز السابقة ويُعيد رمزاً واحداً |
| ٤ | `device_switch_code_verify` | **service_role فقط** — تحقق + استهلاك + أحداث |
| ٥ | `session_is_sensitive` | **service_role فقط** — يستخدمها `staff-login` |
| ٦ | `admin_session_list` / `admin_session_end` | تقنية المعلومات: عرض جلسات أي حساب وإنهاؤها (`require_it_admin`) + تدقيق `by_it` |
| ٧ | `staff-login` | يطلب الرمز للحساب الحسّاس قبل تطبيق الانتقال، ويُبطل الجلسة الجديدة عند الفشل |
| ٨ | صفحة الدخول | حقل رمز (٦ أرقام) + تعطيل الزر حتى يكتمل + شرح مكان الرمز |
| ٩ | «أجهزتي» | صندوق «الدخول من جهاز جديد» بإنشاء رمز وعرضه |
| ١٠ | صفحة المستخدم في IT | بطاقة «جلسات الحساب»: الأجهزة والـIP والوقت + إنهاء جلسة/الكل |

## ٥) حدود

1. الرمز يُعرض **مرة واحدة** في الشاشة؛ إن أُغلق الصندوق يُنشأ رمز جديد (القديم يُلغى).
2. لا يوجد إشعار لصاحب الحساب بأن رمزاً أُنشئ — يُسجَّل حدث `switch_approved` بـ`action=device_code_created` في سجل الأمان، ويُعرض في لوحة المراقبة (الجولة ٤).
3. الفرض ما زال معطّلاً افتراضياً: لا يُطلب رمز من أحد حتى تُضبط سياسة الحساب.
4. رمز الوصول للجلسة المنتهية يبقى صالحاً حتى انتهاء صلاحيته (ساعة) — حدّ GoTrue.
