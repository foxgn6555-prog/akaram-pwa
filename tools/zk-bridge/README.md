# وكيل جسر الشبكة الداخلية (zk-bridge)

يسحب سجلات الحضور مباشرة من أجهزة ZKTeco (بروتوكول ZK الثنائي، TCP/UDP منفذ **4370**) من حاسوب داخل شبكة الجهة،
ويرسلها إلى منصة أكرم عبر `biometric-bridge` بمفتاح لكل جهاز. لا يحتاج الجهاز إلى إنترنت ولا يحتاج الخادم إلى VPN.

يعوّض ما يفوت ADMS (الدفع لا يعيد السجلات القديمة) لأنه يقرأ **كل** ما في ذاكرة الجهاز، والمنصة تزيل التكرار.

## التشغيل
1. Node.js 18+ على حاسوب يرى الجهاز (اختبر: `ping <ip>` ثم المنفذ 4370 مفتوح).
2. `npm install` داخل هذا المجلد (يثبّت `node-zklib`).
3. في بوابة التطوير المركزية → البصمة → سجّل المصدر بنمط **وكيل الشبكة الداخلية** → «توليد مفتاح الجهاز» → انسخ مقتطف `config.json`.
4. احفظه هنا باسم `config.json` وعدّل `ip` (وكذلك `comm_key` إن كان Comm Key مضبوطاً في الجهاز).
5. `npm run test-device` → يطبع عدد السجلات ووقت الجهاز بلا إرسال.
6. `npm start` (دائم) أو `npm run once` من مجدول ويندوز/cron كل 5 دقائق.

## ملاحظات
- الوقت يُرسل كما هو من الجهاز (محلي) وتحوّله المنصة بمنطقة الجهاز المسجلة (`timezone_offset`) — منطقة الحاسوب لا تؤثر.
- `state.json` يحفظ آخر وقت مُرسل لكل جهاز (إرسال تزايدي بهامش 24 ساعة). احذفه لإعادة إرسال كل شيء (آمن — تكرار يُهمل).
- المكتبة لا تعيد اتجاه الدخول/الخروج؛ يُشتق في المنصة (أول بصمة دخول/آخر بصمة خروج).
- فشل الاتصال بالجهاز يُبلَّغ للمنصة ويظهر في «سجل العمليات» وعلى بطاقة المصدر.
- تدوير المفتاح من البوابة يُبطل القديم فوراً — حدّث `config.json`.
